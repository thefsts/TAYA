# OBJECTIVE 1 — PREVENT PAID EVENTS FROM FAILING SILENTLY ON A BAD COURSE SLUG

## Current Risk

Events are currently contact-only and do not use online checkout.

However, if a future event is enabled for online payment and passes a `courseSlug` into:

```text
POST /api/square/create-order
```

a missing or mistyped course slug may cause:

```ts
resolveCoursePayment(...)
```

to return `null`.

That can produce a vague or silent booking failure instead of clearly identifying that the event configuration is invalid.

We need an explicit guard so every event enabled for online payment references a real and payable course in the course catalog.

---

# REQUIRED EVENT PAYMENT CONTRACT

Review:

```text
corsair-source/src/data/events.ts
corsair-source/src/lib/pricing.ts
corsair-source/src/app/api/square/create-order/route.ts
tests/pricing/src/
```

Use the existing event data model where possible.

If the event model does not currently have an explicit payment flag, introduce a clear field such as:

```ts
paymentMode: "contact" | "online";
```

or:

```ts
onlinePaymentEnabled: boolean;
```

Do not infer payment eligibility merely from the presence of a `courseSlug`.

The configuration should clearly distinguish:

```ts
{
  paymentMode: "contact"
}
```

from:

```ts
{
  paymentMode: "online",
  courseSlug: "shotgun-course"
}
```

# CATALOG GUARD

Add a reusable validation function that checks all online-payment events.

Suggested behavior:

```ts
type EventPaymentValidationResult =
  | { valid: true }
  | {
      valid: false;
      eventId: string;
      eventTitle: string;
      reason:
        | "missing-course-slug"
        | "unknown-course-slug"
        | "course-not-payable";
      courseSlug?: string;
    };
```

Suggested function:

```ts
export function validatePaidEventCourseReferences(
  events: EventDefinition[],
  courses: CourseDefinition[],
): EventPaymentValidationResult[];
```

Or use a similarly clear implementation consistent with the existing architecture.

For each event flagged for online payment:

1. `courseSlug` must be present.
2. The slug must exactly match a course in the course catalog.
3. The referenced course must be eligible for website/Square payment.
4. External-only or contact-only courses must not be accepted as payable event targets.

Contact-only events must not be required to have a course slug.

# ROUTE-LEVEL ERROR HANDLING

Update:

```text
corsair-source/src/app/api/square/create-order/route.ts
```

A malformed event payment request must produce a clear client-visible error response.

Do not return a successful response with a zero total.

Do not silently swallow a `null` pricing result.

Use clear HTTP status codes.

Recommended behavior:

## Missing course slug for an online event

```text
HTTP 400
```

Example response:

```json
{
  "error": "Online-payment event is missing a courseSlug."
}
```

## Unknown course slug

```text
HTTP 400
```

Example response:

```json
{
  "error": "The referenced course could not be found.",
  "code": "UNKNOWN_COURSE_SLUG"
}
```

## Known but non-payable course

```text
HTTP 400
```

Example response:

```json
{
  "error": "The referenced course is not eligible for online payment.",
  "code": "COURSE_NOT_PAYABLE"
}
```

## Unknown or invalid add-on

Keep the existing strict behavior:

```text
HTTP 400
```

Do not expose internal stack traces, Square credentials, environment variables, or sensitive configuration.

---

# NO ZERO-DOLLAR FALLBACK

Explicitly prevent these outcomes:

```ts
amountCents = 0;
```

or:

```ts
lineItems = [];
```

for a paid course or event request caused by a bad slug.

Before calling Square, assert that:

- The course exists
- The course is payable
- The resolved amount is valid
- At least one legitimate base course line item exists
- The total is greater than zero for paid Corsair courses

If any assertion fails, return a clear HTTP 400 error before making a Square API call.

====================
COURSE/SERVICE PRICE SOURCE OF TRUTH
====================================

Create a single price/catalog source file in the website, such as:

src/lib/pricing.ts
or
src/data/catalog.ts

Each item should include:

```ts
{
  id: string;
  slug: string;
  name: string;
  type: "course" | "service" | "event";
  category: string;
  description: string;
  priceCents: number;
  currency: "USD";
  squareCatalogItemId?: string;
  squareVariationId?: string;
  active: boolean;
}
```

Do not scatter prices across multiple components.

All course cards, course detail pages, checkout, and schema should read prices from this single source.

====================
PRICE VALIDATION RULE
=====================

Never trust prices sent from the frontend.

When checkout starts:

* frontend sends item slug/id only
* server looks up price from trusted catalog source
* server creates Square payment with server-side price
* server includes item name, slug, and category in metadata/reference_id/order note if possible

====================
SQUARE PAYMENT FLOW
===================

Use Square Web Payments SDK on frontend.

Create API routes/server actions:

/api/square/create-payment
/api/square/create-order
/api/square/webhook
/api/square/catalog-check
/api/square/catalog-sync

Payment flow:

1. User selects course/service/event.
2. User fills registration fields.
3. User signs waiver if course requires it.
4. User clicks Pay Securely with Square.
5. Frontend uses Square Web Payments SDK.
6. Backend creates/charges payment through Square.
7. Success redirects to /confirmation.
8. Failure shows clear retry message.

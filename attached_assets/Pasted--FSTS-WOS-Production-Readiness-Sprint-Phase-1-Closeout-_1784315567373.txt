# PHASE 1 SECURITY CLOSEOUT

The deep security audit confirmed that the core CMS modules already use `requireSiteAccess()` or `checkSiteAccess()` consistently.

The following security gaps were identified and fixed:

## Fixed Findings

### `users.promoteToSuperAdminByClerkId`

Previously had no authorization check.

It must now require an authenticated SuperAdmin caller.

Test access may be permitted only in an explicitly approved non-production environment.

### `users.upsertTestSuperAdmin`

Previously allowed an unauthenticated caller to create a test SuperAdmin account.

It must remain locked to approved test environments only.

### `squareOrders.syncCatalog`

Previously allowed unauthenticated callers to trigger a site’s Square catalog synchronization.

It must require authenticated, write-capable access to the requested site.

### `siteSettings.generateUploadUrl`

Previously allowed any logged-in user to obtain an upload URL.

It must require site-scoped write access.

### `siteSettings.getFileUrl`

Previously resolved storage URLs without authentication.

It must require an authenticated, active user.

### `forms.submitToForm`

This remains public by design for anonymous submissions to published forms.

Rate limiting and abuse protection will be handled during the public-endpoint security phase.

## What this proves

The Phase-1 editor pipeline works end-to-end on a real (fixture) site: a live
HTML site is crawled, folded into the stable §5 content map, and resolved into
the §6 safe insertion zones the client editor renders. This is the
"use it myself" acceptance test — it exercises the **real** production modules,
not a reimplementation:

```
fixture HTML → crawlSite()        (§4 route discovery + page models)
             → buildPageMap()      (§5 stable content map)
             → zonesForPageKeys()  (§6 safe insertion zones)
```

## Empirically verified zone resolutions

Captured from the real pipeline (see `captured-snapshot.json`):

| Page | Resolved §6 zones |
|---|---|
| `/` | `hero`, `service-list`, `footer-content`, `video-section`, `cta-stack` |
| `/about` | `content`, `video-section`, `cta-stack` |
| `/knowledge-center` | `content`, `faq-list`, `video-section`, `cta-stack` |

`video-section` and `cta-stack` are **additive** zones
(`ADDITIVE_ZONE_IDS` in `convex/lib/editorZones.ts`) — available on every page
the map knows. The page-specific zones come from the §5 key grammar:

- `/` — `home.hero.*` → `hero`; `home.services.items[…]` → `service-list`;
  `home.footer.text` → `footer-content`.
- `/about` — the lead block on a non-home page takes the `intro` role
  (`sectionRoleFor`), so `about.intro.*` → `content`.
- `/knowledge-center` — `knowledge-center.intro.*` → `content`; the
  "Frequently Asked Questions" section matches the `faq` vocabulary →
  `knowledge-center.faq.*` → `faq-list`.

## Test coverage (6 tests)

1. `crawlSite` discovers all three fixture pages.
2. `buildPageMap` folds a stable content map (home-first ordering, keyCount > 0).
3. Resolves the expected §6 insertion zones on every page.
4. Determinism — two crawls yield identical maps + zones.
5. Additive zones (`video-section`, `cta-stack`) present on every page.
6. Capture mode writes `captured-snapshot.json` when `TAYA_CAPTURE_SNAPSHOT=1`.

## Design notes / honest boundaries

- **Offline by construction.** `fetch` is stubbed to serve only the fixture
  pages; every other URL 404s. No network is touched, so the harness is
  deterministic and CI-safe. The crawl's §4 "auto" contract tolerates partial
  sites, so 404s elsewhere are expected and harmless.
- **Single source of truth.** `capture-snapshot.mjs` does **not** re-implement
  the pipeline — it runs the harness test in capture mode, which writes the
  snapshot as a side effect. The pipeline can therefore never drift between the
  script and the test.
- **Fixture scope.** The fixture is deliberately minimal: the site-wide footer
  is represented on the homepage. Inner pages carry only their own lead/section
  content, which is why they resolve no `footer-content` zone. This matches the
  empirically-verified resolutions above and keeps the fixture focused on the
  zone-resolution contract under test.
- **No new production behavior.** E9 adds tests + fixtures + docs only; no
  runtime module was modified.
